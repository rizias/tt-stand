# MongoDB через SSH

Читайте при поиске документов, обходе связей, подсчётах и агрегациях MongoDB.
Все примеры используют вымышленные базы, коллекции и идентификаторы.

## Подключение

Владелец заполняет `profile.json` и соседний `credentials.json`. Сервер MongoDB
ссылается на именованный SSH-сервер того же профиля. `privateKeyPath` задаёт путь
к приватному ключу, `knownHostsPath` задаёт файл известных SSH-серверов.
Инструмент проверяет предъявленный ключ сервера по этому файлу.

Агент получает настройки командой `tt-stand config --profile investigation --json`.
Секретные поля описаны признаками заданности и источниками. Профиль, файл доступа
и приватный ключ читает исполняемый tt-stand. Агенту запрещено напрямую читать
эти файлы или изменять заполненные значения без прямой просьбы владельца.

При единственном сервере MongoDB он выбирается автоматически. Для нескольких
передайте `--server <имя>`. База выбирается из `--database`, затем `defaultDatabase`
выбранного сервера. `listDatabases` выполняется в `admin`. `ping`, `hello` и
`buildInfo` используют `admin`, если база не задана.

Схема профиля приведена в [configuration.md](configuration.md).

## Документ команды

```text
tt-stand mongo --profile investigation --query-file investigation-a/collections.json
tt-stand mongo --profile investigation --server mongodb --database shop --query-file investigation-a/order.json
```

Файл содержит один стандартный документ команды MongoDB в JSON или Extended JSON.
Имена коллекций, фильтры, проекции, сортировки и стадии соответствуют MongoDB.
JSON-файл позволяет сохранить кавычки и знаки `$` при вызове через PowerShell,
cmd.exe, bash и zsh. UTF-8 BOM допускается.

Разрешены `find`, `aggregate`, `count`, `distinct`, `listDatabases`, `listCollections`,
`listIndexes`, `collStats`, `dbStats`, `explain`, `ping`, `hello`, `buildInfo`.
У каждой команды проверяются разрешённые аргументы и их структура. Поддержка
новой команды или нового оператора добавляется в проверяемый реестр инструмента.

`mongosh`-выражения вида `db.orders.find(...)` замените их стандартным документом
команды, например `{"find":"orders","filter":{}}`.

## Последовательное расследование

### 1. Получить коллекции

Содержимое `investigation-a/collections.json`.

```json
{ "listCollections": 1, "nameOnly": true }
```

При полном успешном ответе `data` содержит список доступных коллекций. Названия для следующих
запросов агент берёт из ответа или из постановки задачи.

### 2. Найти документ

Содержимое `investigation-a/order.json`.

```json
{
  "find": "orders",
  "filter": { "number": "ORDER-42" },
  "limit": 1
}
```

```text
tt-stand mongo --profile investigation --query-file investigation-a/order.json
```

Допустим, в документе найдено поле `customerId` со значением
`{"$oid":"507f1f77bcf86cd799439011"}`. При `hitLimit: true` за лимитом могут быть
другие совпадения. Единственность документа устанавливается отдельной проверкой.

### 3. Прочитать связанный документ

Агент переносит полученное значение с сохранением BSON-типа в
`investigation-a/customer.json`.

```json
{
  "find": "customers",
  "filter": { "_id": { "$oid": "507f1f77bcf86cd799439011" } }
}
```

```text
tt-stand mongo --profile investigation --query-file investigation-a/customer.json
```

Связь между ответами устанавливает агент. Каждый вызов исполняет переданный фильтр
и возвращает самостоятельный ответ. Для другой базы добавьте `--database archive`.

### 4. Посчитать документы

```json
{ "count": "orders", "query": { "customerId": { "$oid": "507f1f77bcf86cd799439011" } } }
```

### 5. Выполнить агрегацию

```json
{
  "aggregate": "orders",
  "pipeline": [
    { "$match": { "status": "failed" } },
    { "$group": { "_id": "$customerId", "count": { "$sum": 1 } } },
    { "$sort": { "count": -1 } }
  ],
  "cursor": {}
}
```

Вложенные pipeline в `$lookup`, `$facet` и `$unionWith` проверяются тем же способом.
`$set` и `$unset` в агрегации преобразуют возвращаемые документы.

## Параллельные агенты

Каждый процесс владеет своим SSH-подключением, MongoDB-клиентом, базой и курсором.
Локальный порт выбирает ОС. Запросы MongoDB, Grafana и Kubernetes могут выполняться
одновременно. Завершение одного вызова освобождает его соединения.

Передавайте `--profile` в каждом вызове. Для общей задачи используйте согласованное
значение `TT_STAND_RUN`, для отдельных расследований задайте разные значения.
`--database` действует на один вызов. Для файлов запросов выделите отдельную папку
каждому агенту, например `investigation-a/` и `investigation-b/`.

Каждая запись журнала имеет уникальное имя с UUID и публикуется целиком.
Журнал сохраняет запрос, ответ, профиль, базу, процесс и метку расследования.
Пути записей возвращаются в `echo.journal`, метка в `echo.journalRun`.

## Полнота результата

Курсор вычитывается до конца внутри вызова. `batchSize` регулирует размер порции.
`limit` задаёт ограничение числа документов. `singleBatch: true` явно ограничивает
ответ одной порцией и отражается в неполноте. Отметка сервера `partialResultsReturned`
также делает ответ неполным.

При обрыве возвращаются полученные документы, причина неполноты и ненулевой код
завершения. Успешный пустой `data` относится к фактическому фильтру и выбранной базе.
Проверяйте `ok`, `incomplete`, `incompleteReasons` и `echo` перед выводом.

Canonical Extended JSON сохраняет ObjectId, Int64, Decimal128, дату, бинарные поля,
регулярные выражения и BSON Undefined.
Для следующего запроса переносите BSON-значения целиком. MongoDB-поле `record`,
`http` или `environment` выводится как обычное поле документа.

Входное значение `{"$undefined":true}` отклоняется с `bad_request`, потому что драйвер
кодирует его как BSON Null. Для поиска BSON Undefined используйте фильтр `{"field":{"$type":6}}`
с нужным именем поля.
Входной `$dbPointer` также отклоняется из-за подмены BSON-типа драйвером.
Для поиска DBPointer используйте `{"field":{"$type":12}}`.

Диапазон BSON Date шире диапазона JavaScript Date. Если драйвер вернул дату за
пределами ±8 640 000 000 000 000 миллисекунд от Unix epoch, команда сообщает
`mongo_query_failed` и неполноту с уже полученными документами.

Драйвер преобразует BSON DBPointer и DBRef в одинаковый объект. При таком значении
команда сообщает `mongo_query_failed` и возвращает уже полученные документы с признаком неполноты.

## Проверка запросов

Проверка выполняется до загрузки настроенных секретов подключения и открытия SSH. Инструмент отклоняет
изменяющие команды, неизвестные аргументы и операторы, `$out`, `$merge`, `$where`,
`$function`, `$accumulator`, map-reduce и произвольные скрипты. Буквальные значения
в `$literal` и `$const` обрабатываются как данные.

Бесконечные запросы `tailable`, `awaitData` и `$changeStream` отклоняются.
Служебные `getMore` и закрытие курсора выполняет инструмент для своего курсора.
Проверка действует при любых правах учётной записи MongoDB.

## Диагностика

| Класс                              | Действие                                                           |
| ---------------------------------- | ------------------------------------------------------------------ |
| `bad_request`                      | исправить стандартный документ команды по указанному пути поля     |
| `ssh_connection_failed`            | проверить доступность SSH-сервера и таймаут через tt-stand         |
| `ssh_host_key_invalid`             | сообщить владельцу о несоответствии known_hosts                    |
| `ssh_auth_failed`                  | попросить владельца проверить ключ и парольную фразу               |
| `mongo_auth_failed`                | попросить владельца проверить MongoDB-доступ и authSource          |
| `mongo_access_forbidden`           | сообщить, для какой команды недостаточно прав чтения               |
| `mongo_query_failed`               | сверить запрос, выбранную базу и поддерживаемые сервером параметры |
| `timeout_client`, `stream_aborted` | проверить частичный результат и повторить необходимое чтение       |

Адреса узлов MongoDB должны быть доступны со стороны SSH-сервера. Соединения
к обнаруженным узлам replica set также идут через SSH. Для `mongodb+srv` драйвер
выполняет DNS SRV/TXT-разрешение локально, поэтому соответствующая DNS-зона должна
быть доступна машине, на которой запускается tt-stand.
