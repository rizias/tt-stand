# Повторяемый анализ из терминала

`batch` выполняет заранее подготовленные команды метрик и логов. Это одна команда
для человека и агента; агент для её запуска не требуется.

```text
tt-stand batch --file local/plan.json --start -8h --end now --out results/night --view local/view.json
```

В PowerShell с запретом сценариев используйте `tt-stand.cmd`. Выражения находятся
в файлах, аргументы не проходят через собственную оболочку исполнителя пакета.
Каталог результата должен быть новым или пустым. Команда не перезаписывает файлы.

## План

```json
{
  "version": 1,
  "goal": "Потребление ресурса и частота запросов за период",
  "requests": [
    {
      "id": "cpu",
      "why": "Ресурс по участникам во времени",
      "argv": ["metrics", "query", "--query-file", "queries/cpu.promql"]
    },
    {
      "id": "http",
      "why": "Запросы по маршрутам во времени",
      "argv": ["logs", "query", "--query-file", "queries/http.logsql"]
    }
  ]
}
```

Файлы выражений уже содержат законченные PromQL/LogsQL. Их пути в `argv` относительны
папке плана, абсолютные пути тоже допустимы. Никаких подстановок в выражения нет.
Четыре команды `metrics` и четыре команды `logs` доступны в пакете. Все пункты
проверяются локально до первого запроса; синтаксис языка проверяет сервер.

`--start`/`--end` пакета наследуются только командами, которые их поддерживают,
если пункт не задал собственное значение. `step` и `time` не вычисляются.
Период и выражения уходят как даны. Профиль и конфигурация задаются только пакету.
Внутри пунктов нет запуска внешних программ, условий, `init`, `update` или другого batch.

## Представление

```json
{
  "version": 1,
  "timezone": "UTC",
  "panels": [
    {
      "kind": "line",
      "response": "cpu",
      "format": "prometheus-matrix",
      "labelKeys": ["namespace", "pod"],
      "unit": "cores"
    },
    {
      "kind": "line",
      "response": "http",
      "format": "logs-records",
      "timeField": "_time",
      "timeEncoding": "rfc3339",
      "valueField": "requests",
      "groupFields": ["upstream", "method", "path"],
      "unit": "requests"
    }
  ]
}
```

`response` — id пункта плана. Поля выбираются по фактическому ответу вашей установки.
`labelKeys` задаёт подпись, разные серии не объединяются. Часовой пояс меняет подписи,
а не запросы. Неполнота, отсутствующие поля и ошибки показываются; ноль не подставляется.

Главная страница показывает до 10 ведущих текущих рядов по полному максимуму и
добавляет однозначные базовые пары. Все ряды находятся в каталоге под графиком:
нажмите «Выбрать объект», найдите его по меткам и нажмите «Показать». Во время
загрузки кнопка недоступна, после успеха она помечена «Выбрано». Каталог закрывается,
фокус возвращается к нужному графику. «Все объекты» возвращает обзор. Подписи округляются только
для чтения; статистика и детали используют полные числа. Общая ось времени и
полные пики вычисляются до отбора рядов. Для длинного графика используются
min/max временных корзин; обработка названа, исходные разрывы сохраняются.

Необязательный `title` задаёт заголовок страницы или панели. `yMin` и `yMax`
задаются вместе конечными возрастающими числами, если нужен фиксированный масштаб.
`description` объясняет смысл показателя. У каждой линейной панели обязателен `unit`;
для безразмерного показателя укажи `"none"`. Он отображается как «Единица: не указана»
без суффикса числа. В корне view обязателен явный IANA `timezone`. Среднее в каталоге — арифметическое по конечным
измерениям за весь сохранённый период; это не среднее, взвешенное по времени.

Панели идут одной колонкой на полную ширину. «Развернуть» открывает большой график
поверх страницы, закрытие возвращает на прежнее место. «Приблизить», «Отдалить»,
«Влево», «Вправо», «Весь период» и выделение участка мышью управляют временем.
При приближении берутся все точки только видимых объектов из сохранённых файлов.
«Масштаб по данным» подбирает Y к выбранным значениям, «Общий масштаб Y» возвращает
масштаб обзора. Даты и пояс показаны рядом с управлением.

## Переход в Grafana

«Открыть исходный запрос в Grafana» использует сохранённый запрос, UID/тип источника
и выбранный на графике период. Выбранный объект в выражение не дописывается.
Настройки Grafana берутся из `view.grafana`, если он задан, иначе из `manifest.grafana`.
Пример поля в view — `grafana: {"baseUrl":"https://grafana.example.invalid","orgId":1}`.
`orgId` необязателен. Разрешён только http(s) без учётных данных, query и fragment.
Поддерживаются query-модели Prometheus, VictoriaMetrics и VictoriaLogs; неизвестный
тип помечается как недоступная точная ссылка. Переход использует обычные права
пользователя в Grafana, а область профиля tt-stand указана в сохранённом ответе.
Формат — [официальный Explore URL](https://grafana.com/docs/grafana/latest/visualizations/explore/get-started-with-explore/#generate-explore-urls-from-external-tools).

## Данные для анализа агентом

Начните с `manifest.json` и `report/analysis.json`. Последний содержит названия,
единицы, описания, определения статистики, все метки и неокруглённые значения,
исходные запросы, периоды, namespaceScope, ошибки/неполноту и пути полных ответов
и CSV. График и HTML для численного анализа не нужны. `objects[].max/mean` относятся
ко всему сохранённому периоду, а не к выбранному человеком участку графика.
Для анализа конкретного участка читайте полный `sources[].responseFile`.

Таблица: `kind: "table"`, `format: "logs-records"`, `columns` — имена полей.
Для HTTP-сводки добавьте `transform: "http-summary"` и `mapping` с `groupFields`,
`countField`, `durationSumField`, `maxField`. Среднее равно сумме длительностей/числу
запросов; готовые p95 не складываются и длительность HTTP не выдаётся за CPU.
В обзоре до 20 строк с наибольшей суммой `response_seconds`. Кнопка загрузки
детализации включает поиск и сортировку всех строк, страницы содержат до 20 строк.
Для обычной таблицы необязательный `rankField` называет колонку ранжирования;
без него сохраняется порядок источника. Для `http-summary` создаётся отдельный CSV
со строками сводки. Обычная таблица доступна в отчёте и исходном JSON.

Интервалы: `kind: "interval"`, `format: "rows-file"`, `file`, `startField`, `endField`,
`labelField`, `timeEncoding`. Файл относителен view и содержит массив объектов.
Поддерживаемые времена: `rfc3339`, `unixSeconds`, `unixMilliseconds`.
Необязательный `fields` — список дополнительных полей строки для подсказки.
Отсутствующие поля не придумываются. Интервал билда не означает интервал выполнения
тестов: для точной фазы нужен соответствующий файл источника.

## Файлы результата

- `plan.json` — неизменяемый план запуска.
- `manifest.json` — завершённые пункты, их статусы, файлы и время.
- `responses/` — полные обычные ответы, с текущей областью профиля.
- `requests.ndjson` — наблюдаемые попытки Grafana, включая служебные чтения.
- `report/report.html` и CSV — при явном `--view`.
- `report/detail/` — полные точки каждого ряда и строки таблиц для загрузки по выбору.

В stdout только сводка и пути. Отказ источника не отменяет независимые следующие
пункты. Неполнота сохраняется; ошибка записи останавливает новые чтения.
`output_write_failed` означает отказ записи, `report_render_failed` — отказ
представления. Время в сводке клиентское, не время выполнения на сервере.
`fetchAttempts` не включает скрытые redirects или чужие CLI.

Откройте `report.html` обычным браузером. Обзор работает без сети; детализация
загружается из соседней папки `detail/`, в том числе через `file://`. При переносе
сохраните всю папку `report/`, чтобы поиск полных данных оставался доступен.
Отсутствующий файл детализации показывается ошибкой с путём, а не пустым результатом.
Большая модель обзора с baseline хранится с gzip без потери чисел и меток; её
распаковывает встроенный браузерный `DecompressionStream`. При отсутствии этой
возможности или повреждении данных HTML называет ошибку и даёт ссылки на CSV и
источники. Полные исходные ответы не сжимаются и не изменяются обработчиком.

## Новая ночь и релиз

Повторите тот же план с новым периодом и новым `--out`. Данные снимаются заново.
Для сравнения передайте предыдущий результат:

```text
tt-stand batch --file local/plan.json --start -1h --end now --out results/after --view local/view.json --baseline results/before/manifest.json
```

Сравнение использует уже сохранённый baseline, не обращается за ним к серверу.
Совпадение по времени не доказывает причину; график не заменяет критерии приёмки релиза.

Можно заново построить представление без снятия данных:

```text
node "<путь-к-скиллу>/references/analysis/render.mjs" --manifest results/night/manifest.json --view local/view.json --out results/new-view
```

Настоящие имена, выражения и view храните в своих файлах рядом со скиллом,
вне `references/`. Программа обновляет общие ресурсы и сохраняет ваши соседние файлы.
Для нескольких проектов можно хранить рецепты в `~/.tt-stand/recipes/`: `README.md`
называет назначение и профиль каждого рецепта и приводит готовую команду. Эти файлы
принадлежат пользователю; установщик пакета их не создаёт и не обновляет.

## Подготовка повторяемого анализа

До первого обращения определите требуемый ответ, охват и период. Проверьте наличие
`~/.tt-stand/recipes/` и прочитайте его `README.md`, если файл существует, для выбора
рецепта и профиля. Прочитайте рабочие
рецепты в файлах пользователя, выберите только нужные выражения и назовите роль
каждого чтения. Подготовьте пакет и view, затем снимайте данные. Недостающий конкретный
факт проверяется целевым чтением; новый день получает новые данные, а не старый снимок.
Дополняйте план только для исходного вопроса, ошибки/неполноты или найденной зависимости.

Человек и агент запускают один и тот же сценарий:

```text
tt-stand batch --file local/plan.json --start -8h --end now --out results/night --view local/view.json
```

Полные ответы лежат в `responses/`, сводка и пути — в stdout. Таблицы и графики
строятся локально без новых запросов. `--baseline <manifest.json>` сравнивает с
предыдущим снятием, не доказывая причинность или отсутствие всех проблем.

Общие примеры — в `references/examples`, обработка — в `references/analysis`.
Настоящие выражения, поля и соответствия держите в пользовательских файлах вне
`references/`; обновление их сохраняет.

Обзор HTML и полнота данных — разные проверки: проверь число рядов/точек, полный
каталог и загрузку ряда вне обзора, поиск строки вне первых 20, ошибки и baseline.
Для численного анализа сначала читай `manifest.json` и `report/analysis.json`:
там названия и единицы показателей, определения статистики и пути полных ответов.
Среднее по измерениям не является средним по времени; статистика каталога относится
к полному периоду. Для выбранного участка считай по исходным точкам из JSON.
Человек открывает `report.html`; переносится вся папка `report/` с `detail/` и CSV.
Не объявляй удобство и скорость доказанными только по успешным HTTP или тестам кода:
измерь размер/время настоящего HTML и проверь его в браузере.
