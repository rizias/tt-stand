В папке этого скилла могут лежать файлы пользователя — всё, кроме `SKILL.md` и `references/`. Прежде чем работать, посмотри список файлов папки скилла и прочитай файлы пользователя: это его правила и заметки к этому скиллу. Профили, файлы учётных данных и приватные ключи не открывай. При расхождении со скиллом прав пользователь.

Полезные сведения о стенде предложи сохранить в пользовательском файле рядом со скиллом.
Пиши только после его согласия. Значения паролей, токенов и секретов не записывай никогда.

Настройки проверяй через `tt-stand config --json` и `tt-stand config profiles`.
Профили, credentials и приватные SSH-ключи читает только инструмент. Заполненные файлы
меняются по прямой просьбе пользователя, значения доступа он вписывает самостоятельно.

Перед запросом определи нужный результат, период и профиль. После запроса проверь `ok`,
`echo`, `incomplete` и `incompleteReasons`. Выражения со спецсимволами передавай через `--query-file`.
Подробности читай из нужного файла справки по задаче.

## Первый запуск

Если программа отсутствует, установи её.

```text
npm install --global @rizias/tt-stand
```

`tt-stand init` предлагает отдельные каталоги установки. Выбери один каталог используемого агента.
Для установки в проект без диалога укажи нужное назначение.

- Codex или OpenCode — `tt-stand init <путь к проекту> --for agents`.
- Claude Code — `tt-stand init <путь к проекту> --for claude`.

Несколько копий устанавливай при явном запросе пользователя. Уже установленный скилл доступен для работы.

Для нового подключения выполни `tt-stand config init`. Оно создаёт профиль `default`.
Именованный профиль создаётся через `config init --profile <имя>`. Профиль выбирается через
`--profile <имя>`, `TT_STAND_PROFILE`, `defaultProfile` либо как единственный доступный.
`--config <путь к config.json>` выбирает общий файл. `--server <имя>` выбирает сервер MongoDB.

| Поле                                                    | Назначение                     | Где взять значение               |
| ------------------------------------------------------- | ------------------------------ | -------------------------------- |
| `grafana.baseUrl`                                       | адрес Grafana                  | у владельца подключения          |
| `grafana.credentialsFile`                               | путь к файлу доступа           | расположение credentials профиля |
| `grafana.datasourceUid`, `grafana.metricsDatasourceUid` | источники логов и метрик       | список источников Grafana        |
| `kubernetes.kubeconfig`, `kubernetes.context`           | доступ к кластеру              | у владельца подключения          |
| `servers.<имя>.kind`                                    | вид сервера                    | `ssh` или `mongodb`              |
| SSH `host`, `port`, `username`                          | подключение к SSH              | у владельца подключения          |
| SSH `privateKeyPath`, `knownHostsPath`                  | пути ключа и доверенных хостов | у владельца подключения          |
| MongoDB `uri`, `sshServer`, `defaultDatabase`           | адрес, SSH-сервер и база       | у владельца подключения          |
| `namespaceScope`                                        | область namespace              | у пользователя                   |
| `repositoryRoots`                                       | каталоги исходного кода        | у пользователя                   |

Полный состав настроек и действия при ошибках описаны в `references/configuration.md`.
После заполнения проверь нужный источник через `env`, `k8s pods` или MongoDB `{"ping":1}`.

## Обновление

Если tt-stand сообщил о новой версии, выполни `tt-stand update` и продолжай.
Следующая обычная команда синхронизирует установленные копии скилла. При конфликте файлов копия может быть пропущена.

## Справка

- `references/commands.md` — читать для выбора команды, её аргументов и прав Kubernetes.
- `references/mongodb.md` — читать для поиска документов, агрегаций и последовательных или параллельных MongoDB-запросов.
- `references/output.md` — читать при ошибке, неполноте ответа, непонятном поле или работе с журналом.
- `references/configuration.md` — читать при настройке подключения, выборе профиля или ограничении namespace.
- `references/install.md` — читать, когда программа отсутствует, установка требует пояснений или оболочка мешает запуску.
- `references/batch.md` — читать для пакетных запросов, отчётов и сравнения периодов.
- `references/query-planning.md` — читать для поиска по логам, связи значений с идентификаторами и анализа нагрузки.
- `references/analysis` — использовать для локальной обработки и отображения уже полученных данных.
- `references/examples` — использовать как переносимые примеры запросов и представления результатов.
