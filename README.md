# tt-stand

Консольный инструмент только для чтения: логи окружений из VictoriaLogs через Grafana,
метрики окружений через тот же посредник источников данных Grafana, разбор HTTP-трафика
и токенов, MongoDB через SSH, состояние Kubernetes без `kubectl`, определение namespace окружений и честный
отчёт о полноте результата. Инструмент снимает механику доступа
и разбора, но не решает за пользователя: не порождает вариантов искомого значения,
не режет период, применяет явно заданные лимиты, не сортирует записи и ничего
не скрывает. Данные отдаются как есть; при заданной в профиле области видимости
записи известных namespace вне области исключаются, а неразмеченные логи
показываются с меткой `unknown` и признаком неполноты. Число исключённых из
полученного ответа записей названо в эхе. Исключение — перечень имён меток (`metrics labels` без `--label`): в нём
нет данных namespace, поэтому он выводится целиком при любой области. Порядок
расследования — в скилле `skills/tt-stand/SKILL.md`.

## Установка

```text
npm install -g @rizias/tt-stand
```

Нужен Node.js 22.19.0 или выше. Поддерживаются Windows, Linux и macOS, PowerShell
и POSIX-совместимые оболочки. Клиент Kubernetes встроен, `kubectl` не нужен.

> [!NOTE]
> В PowerShell при политике выполнения `Restricted` обёртка `.ps1` не запускается.
> Вызовите `tt-stand.cmd`, она политикой не ограничена, либо один раз выполните
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. Подробно — в
> [install.md](skills/tt-stand/references/install.md).

## Быстрый старт

```text
tt-stand config init
```

Команда создаёт `~/.tt-stand/config.json` и профиль `default`. Дальше владелец
заполняет два файла профиля вручную.

1. В `~/.tt-stand/profiles/default/profile.json` впишите адрес Grafana полем
   `grafana.baseUrl`. Без него команды логов и метрик отвечают `profile_incomplete`.
2. В `~/.tt-stand/profiles/default/credentials.json` впишите доступ к Grafana.
   Поддерживаются JSON с `kind: "basic"`, `login`, `password` либо `kind: "token"`, `token`.

Проверьте настройки и выполните первый поиск.

```text
tt-stand config profiles
tt-stand config --json
tt-stand env
tt-stand logs search --value "<искомое значение>" --start -2d --end now
```

`config profiles` показывает заполненность профилей. `config --json` показывает
настройки и признаки заданности секретов. `env` проверяет доступ к Grafana и
возвращает namespace окружений.

Для Kubernetes задайте `kubernetes.kubeconfig` и при необходимости `kubernetes.context`.
Проверьте доступ командой `tt-stand k8s pods`.

Для MongoDB добавьте в профиль записи SSH и MongoDB по
[примеру настройки](skills/tt-stand/references/configuration.md#mongodb-через-ssh).
Укажите путь к ключу, known_hosts и базу по умолчанию. После заполнения проверьте
доступ командой `mongo` с документом `{"ping":1}` через `--query-file`.

## Настройка

Файлы инструмента находятся в каталоге `~/.tt-stand`.

```text
~/.tt-stand/
  config.json                      корневые настройки
  profiles/<имя>/profile.json      настройки профиля
  profiles/<имя>/credentials.json  учётные данные профиля
  profiles/<имя>/journal/          журнал вызовов профиля
```

Профиль объединяет доступ к Grafana, кластеру и MongoDB для одного контура,
филиала или стенда. Действующий профиль выбирается флагом `--profile`, иначе
переменной `TT_STAND_PROFILE`, иначе полем `defaultProfile` общего `config.json`.
Если выбора нет и профиль один, используется он. При нескольких профилях без
выбора команда отвечает `profile_ambiguous` и перечисляет их имена.

Общий `config.json` выбирается через `--config <путь к config.json>` либо
`TT_STAND_CONFIG`. Флаг имеет приоритет. Профиль по умолчанию задаётся полем
`defaultProfile` в этом файле.
`config init --profile <имя>` создаёт отдельный профиль. При первой настройке он
становится профилем по умолчанию. При добавлении профиля общий файл сохраняется.
Перезапись существующего профиля требует подтверждения либо `--force`.
Во время параллельных расследований каждый агент указывает профиль явно.

Поля `profiles/<имя>/profile.json` задают доступ и локальные пути.

| Поле                           | Тип                | Умолчание                                      | Что делает                                                                                                                                                                                                               |
| ------------------------------ | ------------------ | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `grafana.baseUrl`              | строка, URL        | нет                                            | базовый адрес Grafana                                                                                                                                                                                                    |
| `grafana.credentialsFile`      | строка, путь       | `credentials.json` в каталоге профиля          | файл с доступом к Grafana                                                                                                                                                                                                |
| `grafana.timeoutSeconds`       | число > 0          | нет                                            | таймаут одного HTTP-запроса. Без поля время ожидания не ограничено                                                                                                                                                       |
| `grafana.datasourceUid`        | строка             | нет                                            | закрепить источник логов. Без поля берётся первый подходящий, остальные названы в пояснении ответа                                                                                                                       |
| `grafana.metricsDatasourceUid` | строка             | нет                                            | закрепить источник метрик, когда подходящих несколько или список источников недоступен. Без поля берётся первый подходящий по типу, все найденные названы в `echo.datasourceNote`, использованный в `echo.datasourceUid` |
| `kubernetes.kubeconfig`        | строка, путь       | `KUBECONFIG`, затем `~/.kube/config`           | путь к kubeconfig, может вести в каталог                                                                                                                                                                                 |
| `kubernetes.context`           | строка             | контекст, объявленный в kubeconfig действующим | имя контекста при нескольких кластерах                                                                                                                                                                                   |
| `namespaceScope`               | список строк       | нет, ограничения нет                           | образцы имён namespace, которые инструмент показывает                                                                                                                                                                    |
| `repositoryRoots`              | список строк, пути | пусто                                          | родительские каталоги с репозиториями, названными по именам образов. Поле нужно для поиска веток командой `image`. Без него вывод содержит версию и SHA из тега                                                          |
| `journal.directory`            | строка, путь       | каталог `journal` внутри профиля               | каталог журнала вызовов профиля                                                                                                                                                                                          |

`config init` явно записывает `kubernetes.kubeconfig` как `~/.kube/config`. Чтобы использовать
`KUBECONFIG`, удалите это поле из созданного профиля.

Доступ к Grafana хранится отдельно, в `credentials.json` профиля. Поддерживаются
`kind: "basic"` с полями `login` и `password` либо `kind: "token"` с полем `token`.
Учётные данные подключения читаются из файла доступа профиля.
Неизвестные флаги отклоняются, их значения исключаются из вывода и журнала.

MongoDB добавляется в словарь `servers` с видами `ssh` и `mongodb`.
MongoDB-сервер содержит URI, имя SSH-сервера и `defaultDatabase`. SSH-сервер задаёт
хост, порт, пользователя, путь к ключу и known_hosts.

| Поле                      | Тип                                   | Умолчание            | Что делает                                                                 |
| ------------------------- | ------------------------------------- | -------------------- | -------------------------------------------------------------------------- |
| `servers.<имя>.kind`      | строка                                | нет                  | вид сервера, `ssh` или `mongodb`                                           |
| SSH `host`                | строка                                | нет                  | адрес SSH-сервера                                                          |
| SSH `port`                | целое число от 1 до 65535             | `22`                 | порт SSH                                                                   |
| SSH `username`            | строка                                | нет                  | пользователь SSH                                                           |
| SSH `privateKeyPath`      | строка, путь                          | нет                  | файл приватного ключа                                                      |
| SSH `knownHostsPath`      | строка, путь                          | `~/.ssh/known_hosts` | файл доверенных ключей SSH-серверов                                        |
| MongoDB `uri`             | строка, URI                           | нет                  | адреса MongoDB, доступные со стороны SSH-сервера, без учётных данных       |
| MongoDB `sshServer`       | строка                                | нет                  | имя записи SSH в том же словаре `servers`                                  |
| MongoDB `defaultDatabase` | строка                                | нет                  | база для запросов без `--database`                                         |
| SSH `timeoutSeconds`      | число от 0 до 2147483.647, исключая 0 | `30`                 | таймаут установления SSH-подключения в секундах                            |
| MongoDB `timeoutSeconds`  | число от 0 до 2147483.647, исключая 0 | `30`                 | общий таймаут вызова, включая подключение и чтение всех порций, в секундах |

У команды `mongo` флаг `--database` выбирает базу для одного запроса, а `--server`
выбирает MongoDB-сервер. Единственный сервер MongoDB выбирается автоматически.
При нескольких серверах команда требует явного выбора.

Агент проверяет доступ через tt-stand. Профиль, credentials.json и приватный ключ
читает исполняемый инструмент. Секреты исключены из описания конфигурации и ошибок
подключения. Данные, полученные запросом, сохраняются полностью.

Профили, расположение настроек, выбор kubeconfig и область namespace описаны
в [configuration.md](skills/tt-stand/references/configuration.md).

| `env`                                                                                                                          | namespace окружений из хранилища логов                               |
| `mongo (--query <JSON> \| --query-file <путь>) [--server <имя>] [--database <база>]`                                           | стандартная читающая команда MongoDB через SSH                       |
| `config [--json]`                                                                                                              | эффективные значения, источники и признаки заданности секретов       |
| `config init [--profile <имя>] [--force]`                                                                                      | создать профиль, перезапись с подтверждением либо --force            |
| `config profiles`                                                                                                              | что настроено в профилях, без раскрытия значений                     |

| `update`                                                                                                                       | обновить пакет до последней версии; отвечает текстом, а не JSON      |

Общие флаги — `--human`, `--json`, `--config <путь к config.json>` и `--profile <имя>`.
Флаги `--server` и `--database` относятся к команде `mongo`.
Порядок выбора описан в разделе настройки. Время принимается как
RFC 3339 или относительно, например `--start -2d --end now`. Значения передаются как даны.

Флаг `--query-file <путь>` заменяет `--query` у любой команды, которая его принимает:
содержимое файла становится выражением запроса дословно. Он нужен, когда выражение
содержит символы, которые оболочка трактует по-своему: `<`, `>`, `|`, `&`, `^`, `%`
и кавычки.

Зачем нужна каждая команда, что лежит в её ответе и какие права нужны в кластере —
в [commands.md](skills/tt-stand/references/commands.md).

## MongoDB и несколько агентов

Запрос передаётся стандартным JSON-документом команды MongoDB. Поддерживаются поиск,
подсчёт, каталог баз и коллекций, агрегации и диагностика. Закрытая проверка аргументов
и вложенных pipeline выполняется перед чтением секретов и соединением. Изменяющие
команды, `$out`, `$merge` и исполнение JavaScript отклоняются.

Каждый вызов владеет отдельными SSH-соединением, MongoDB-клиентом, базой и курсором.
Курсор вычитывается до конца, результат сохраняет типы BSON в Canonical Extended JSON.
Следующий запрос агент строит по полученному документу. Независимые MongoDB, Grafana
и Kubernetes-запросы выполняются параллельно. Метка `TT_STAND_RUN` группирует журнал,
UUID различает вызовы. Файлы запросов каждого агента находятся в отдельной папке.

Подробная последовательность от каталога коллекций до связанных документов и
агрегации приведена в [mongodb.md](skills/tt-stand/references/mongodb.md).

## Контракт вывода

По умолчанию ответ — один документ JSON, с `--human` он человекочитаемый.
`update` печатает текст, а `--help` и запуск без команды показывают справку.

- `ok` и `command`;
- `data` — данные без скрытия, замены и обрезки;
- `summary` — сводка команды;
- `echo` — что фактически выполнено: выражение, период, лимит, упор в лимит, число нечитаемых
  строк, порядок сервера, применённая область видимости, путь записи журнала,
  `ignoredFlags` — переданные флаги, которые эта команда не читает и которые поэтому
  не повлияли на результат;
- `incomplete` и `incompleteReasons` — полон ли результат и почему нет;
- `errorClass` и `error` — машиночитаемый класс и русское объяснение отказа.

Отказ печатается в тот же стандартный вывод и тем же конвертом, включая `summary`
и `echo`.

Код завершения `0` означает, что команда отработала, включая пустой или неполный результат.
Ненулевой код означает отказ.

> [!IMPORTANT]
> Пустой результат при `incomplete: true` не означает «ничего не было».

Полный состав ответа, примеры в обоих режимах и устройство журнала вызовов —
в [output.md](skills/tt-stand/references/output.md).

Пакет сохраняет полные ответы в отдельных файлах и печатает их пути. С явным
`--view` тот же запуск создаёт автономный HTML и таблицы без агента. Для новой ночи
меняются период и каталог результата; `--baseline` добавляет предыдущий результат.
Ручной сценарий и формат файлов — [batch.md](skills/tt-stand/references/batch.md).

## Классы ошибок

| Класс                                                               | Значение                                                                                                     |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `bad_request`                                                       | команда или сочетание аргументов некорректно                                                                 |
| `credentials_missing`, `credentials_incomplete`                     | отсутствует файл доступа или обязательное поле                                                               |
| `auth_failed`, `datasource_list_forbidden`, `datasource_not_found`  | отказ авторизации или поиска источника Grafana                                                               |
| `timeout_client`, `upstream_error`, `stream_aborted`                | отказ сервера, таймаут или обрыв чтения внешнего источника                                                   |
| `ssh_connection_failed`, `ssh_host_key_invalid`, `ssh_auth_failed`  | подключение, проверка ключа сервера или аутентификация SSH                                                   |
| `mongo_auth_failed`, `mongo_access_forbidden`, `mongo_query_failed` | аутентификация, права чтения или выполнение MongoDB-запроса                                                  |
| `metrics_query_rejected`                                            | сервер метрик отклонил выражение запроса или превышен его предел — объяснение сервера целиком в `error`      |
| `config_invalid`, `config_exists`                                   | конфигурация некорректна, явно заданного файла нет, либо файл создан другим процессом во время `config init` |
| `profile_missing`, `profile_ambiguous`                              | профиль не найден или не назван, когда профилей несколько                                                    |
| `profile_incomplete`                                                | в профиле нет части настроек, нужной вызванной команде                                                       |
| `namespace_out_of_scope`                                            | запрошенный namespace не входит в область видимости профиля                                                  |
| `token_invalid`                                                     | compact JWT/JWS, header или payload не разобран                                                              |
| `kubeconfig_missing`, `kubeconfig_ambiguous`, `kubeconfig_invalid`  | kubeconfig отсутствует, неоднозначен или некорректен                                                         |
| `kube_context_missing`                                              | нет действующего контекста или связанного кластера                                                           |
| `k8s_access_forbidden`                                              | RBAC запретил чтение                                                                                         |
| `k8s_resource_not_found`, `k8s_resource_ambiguous`                  | ресурс discovery не найден или неоднозначен                                                                  |
| `k8s_upstream_error`                                                | иной отказ Kubernetes API или транспорта                                                                     |
| `pod_not_found`                                                     | выбранный под отсутствует                                                                                    |
| `git_unavailable`                                                   | git не найден в PATH                                                                                         |
| `skill_copy_skipped`                                                | часть копий скилла не поставлена; причины по каждой копии в `data.skipped`                                   |
| `previous_log_unavailable`                                          | лог предыдущего запуска уже утрачен                                                                          |
| `output_write_failed`                                               | запись результата пакета не удалась, дальнейшее чтение остановлено                                           |
| `report_render_failed`                                              | локальное представление не построено полностью                                                               |

## Скилл для агента

Скилл едет в пакете: `skills/tt-stand/SKILL.md`. В нём порядок расследования: проверка
полноты, варианты искомого значения, разворот «значение → идентификатор», связь HTTP-разбора
с токеном, чтение состояния Kubernetes. Разложить его агентам — команда `init`:

```text
tt-stand init                       # спросит, куда поставить скилл
tt-stand init C:\путь --for claude  # без вопроса: только .claude/skills/
```

| Каталог           | Кто читает      |
| ----------------- | --------------- |
| `.claude/skills/` | Claude Code     |
| `.agents/skills/` | Codex, OpenCode |

Интерактивный `init` предлагает глобальные каталоги `~/.claude/skills`, `~/.codex/skills`,
`~/.agents/skills`, каталоги проекта и произвольный путь. Каждый каталог выбирается отдельно.
Перед записью он показывает
выбранные пути и запрашивает подтверждение. Явные путь проекта и `--for` позволяют
установить скилл без вопроса. Места установки запоминаются в `~/.tt-stand/skills-registry.json`.
После обновления пакета следующая обычная команда синхронизирует копии скилла.
При конфликте файлов копия может быть пропущена. В JSON-ответе `init` поле `data`
называет поставленные и пропущенные копии.

`init` ставит папку скилла целиком: `SKILL.md` и дополнения в `references/` — подробности,
которые агент читает по необходимости. Дополнения обновляются вместе с программой:

- [commands.md](skills/tt-stand/references/commands.md) — команды подробно и права в кластере
- [output.md](skills/tt-stand/references/output.md) — контракт вывода, примеры ответов, журнал вызовов
- [configuration.md](skills/tt-stand/references/configuration.md) — профили, конфигурация, область видимости
- [install.md](skills/tt-stand/references/install.md) — установка и запуск из PowerShell
- [batch.md](skills/tt-stand/references/batch.md) — повторяемый анализ, ручные графики и baseline
- [query-planning.md](skills/tt-stand/references/query-planning.md) — выбор чтений до сети

Свои файлы — правила и заметки о вашем стенде — кладите прямо в папку скилла у агента:
программа их не трогает, агент читает их до начала работы, при расхождении со скиллом
правы вы, а выясненное о стенде агент с вашего согласия записывает туда же.

Другому агенту передайте папку скилла целиком: `SKILL.md`, `references/` и свои файлы.
Скилл описывает, как
пользоваться инструментом, но ничего в нём не включает и не выключает: без скилла все команды
работают так же. Порядок первичной настройки для того, кто устройством профилей не знаком,
тоже лежит в скилле — агент по нему помогает настроить инструмент, а логин, пароль или токен
человек вписывает в файл учётных данных своими руками.

О новой версии инструмент сообщает при выводе в терминал с проверкой раз в сутки.
`tt-stand update` запускает `npm i -g @rizias/tt-stand@latest` и передаёт вывод и код
завершения npm. При следующей обычной команде копии скилла синхронизируются,
а при конфликте файлов могут быть пропущены.

## Разработка

```text
npm ci
npx lefthook install
npm run check
```

`npm run check` последовательно выполняет проверку форматирования Prettier, ESLint,
проверку типов TypeScript, поиск неиспользуемого кода knip, тесты Vitest и сборку.
Эта же команда выполняется в CI и перед публикацией.

| Команда                | Что проверяет или создаёт                  |
| ---------------------- | ------------------------------------------ |
| `npm run format`       | форматирует код и артефакты через Prettier |
| `npm run format:check` | проверяет форматирование                   |
| `npm run lint`         | проверяет правила ESLint                   |
| `npm run typecheck`    | проверяет типы TypeScript                  |
| `npm run knip`         | находит неиспользуемый код и зависимости   |
| `npm test`             | запускает тесты Vitest                     |
| `npm run build`        | собирает TypeScript в `dist/`              |

Один файл тестов запускается командой `npx vitest run test/<файл>.test.ts`.
`npm install` включает git-хуки автоматически. Перед коммитом хуки проверяют
форматирование, линтер и, если установлен `gitleaks`, секреты. Перед отправкой
выполняется весь `npm run check`.

Устройство кода описано в [docs/architecture.md](docs/architecture.md).
Правила работы с репозиторием находятся в [AGENTS.md](AGENTS.md).
